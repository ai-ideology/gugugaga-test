# 0. P0.5 最终结论

本轮共构造 **21 类典型/极端玩家**，覆盖：

- 单一极端人格
- 同领域双人格同时成立
- 跨领域双人格同时成立
- 全领域重度玩家
- 轻度玩家
- 低证据玩家
- Gate 误判后恢复
- 社区接触与独立判断
- 事实冲突
- 情境冲突
- 主人格中心性冲突

整体判断：

```text
现有 P0 框架是可用的，
24人格“分别成立 → 再选主人格”的方向成立。

但在正式冻结前，必须修 5 个结构问题，
其中 2 个属于 P0 级别必须修，
3 个属于 P0.5 补丁。
```

## 必须修的两个问题

### P0.5-FIX-01｜P 不能同时承担“参与度”和“主人格中心性”

当前 P 同时用于：

- 跳题 / 适用性
- Hard Gate
- DomainSalience

这会把：

> “我每天做得最多的内容”

错误解释成：

> “这就是我最在意、最能代表我的内容”。

桌面案例 T20 已经复现：

```text
玩家真正最在意角色与本命，
但因为每天稳定做日课：

P1 = 2
P5 = 3

本命真爱党 Fit ≈ 94
日课打卡派 Fit ≈ 95

现有 MainIndex：
日课打卡派 ≈ 95
本命真爱党 ≈ 85
```

这并不是人格匹配问题，而是**中心性变量定义错位**。

### P0.5-FIX-02｜Gate 恢复必须产生 P_effective，而不能永远只恢复到 1

当前规则允许：

```text
P3=0
→ 后续出现强战斗证据
→ REOPEN
→ 验证后至少提升到 P3=1
```

但高难工程师要求：

```text
P3 >= 2
```

于是会出现：

> 用户前面觉得“高难不是我玩游戏最重要的部分”，选择低参与；
> 后面却明确表现出低配通关、反复凹高难、失败提升挑战欲；
> 系统依然永远无法确认“高难工程师”。

这是 Gate 一题误杀的另一种形式。

# 1. P0.5 测试方法

本轮不是随机捏答案，而按 4 层做验证。

## L1｜人格成立层

检查：

```text
Hard Gate
+
BaseFit
+
独立证据
+
EvidenceQuality
```

是否能让目标人格成立。

## L2｜共鸣人格层

检查：

> 一个真实同时具有多个稳定模式的玩家，是否允许多个共鸣人格同时成立。

特别测试：

- 本命真爱 + 白月光
- 强度经理 + 卡池规划
- 高难工程 + 配队建筑
- 剧情深潜 + 世界观考古
- 探索 + 全收集
- 主游定居 + 日课打卡
- 同好召集 + 攻略课代表

## L3｜主人格层

检查：

```text
MainIndex =
0.60 × Fit
+ 0.20 × DomainSalience
+ 0.10 × EvidenceQuality
+ 0.10 × Distinctiveness
```

是否会把“最频繁做的内容”误判为“最能代表我的内容”。

## L4｜异常路径层

检查：

- P=0 后恢复
- 同构题强冲突
- 事实硬矛盾
- 低证据无人格
- 多面体验派兜底风险
- 节奏免疫体的社区接触 Hard Gate

# 3. 详细验收：通过的核心结构

## 3.1 本命真爱党、白月光守护者、本命雕刻师可以共存

测试结果符合设计目标。

### T01｜极端本命长情

可同时成立：

```text
白月光守护者 Fit ≈ 95
本命真爱党     Fit ≈ 94.6
```

这不是冲突。

玩家可以同时：

- 当前有非常明确的本命核心席位
- 很久以前喜欢的角色也始终保留情感

同域主次由 A01 判断“哪一种更鲜明”，但**A01 不应把另一人格判成不存在**。

### T02｜本命精养雕刻

可同时成立：

```text
本命雕刻师
本命真爱党
```

说明目前：

```text
谁最重要
vs
愿意养多深
```

已经被拆开。

**结论：通过。**

## 3.2 “博爱”与“长情”成功解耦

T03 是一个非常重要的测试。

玩家：

- 同时喜欢很多角色
- 但喜欢过的人并不会被新角色替代

```text

+
白月光守护者
```

说明：

```text

```

没有被错误捆绑为：

> “博爱一定追新”
> 或
> “长情一定只有一个本命”。

**结论：通过。**

# 4. P0.5 发现的问题与修正

# FIX-01｜正式拆分 P 和 M

## 4.1 问题

P 以后只代表：

> **Participation / Applicability  
> 参与度与场景适用性**

不再直接代表：

> “这是不是玩家最重要的乐趣来源”。

## 4.2 新增 M｜Motivational Salience

后台新增：

| 编号 | 动机领域 |
|---|---|
| M1 | 角色 / 抽卡 / 养成 |
| M2 | 剧情 / 世界观 |
| M3 | 战斗 / 高难 / 配队 |
| M4 | 探索 / 收集 |
| M5 | 长期经营 / 日常 / 资源 |
| M6 | 社区 / 二创 / 联机 |
| M7 | 新版本 / 新游 / 迁徙 |

M 不进入 8 维结果页。

它只解决：

> **“这么多成立人格里，哪个最能代表我？”**

---

## 4.3 新增 M01｜核心乐趣排序题

建议在 Gate 后、或核心题进行到中段后出现一次。

### M01

> 如果一款二游只能保留下面这些体验，  
> **请选出对你来说最不能缺的 1～3 项，并按重要性排序。**

选项：

1. 喜欢角色、抽卡与角色养成
2. 剧情、人物故事与世界设定
3. 战斗、高难、机制与配队
4. 地图探索、收集与发现
5. 长期经营、日常、资源积累与账号成长
6. 同好交流、攻略、二创或联机
7. 新版本、新角色、新游戏带来的新鲜体验

### 初始映射

```text
第一重要 = 100
第二重要 = 85
第三重要 = 70

未进入前三，但 P>=2 = 50
P=1 = 35
P=0 = 20
```

这些数值仍属于工程初始值。

---

## 4.4 MainIndex 改为

```text
MainIndex =
0.60 × Fit
+ 0.20 × MotivationalSalience
+ 0.10 × EvidenceQuality
+ 0.10 × Distinctiveness
```

不再用 P 直接代替 MotivationalSalience。

---

## 4.5 跨域人格的 M

### 主游定居派 / 版本活动特种兵

使用：

```text
max(M5, M7)
```

### 攻略课代表

使用：

```text
max(M3, M5, M6)
```

### 全收集派

使用：

```text
max(M1, M4, M5)
```

### 多面体验派

使用：

```text
MultiSalience = mean(最高的4个 M)
```

避免再次把 F3/F4 同时放进：

- Fit
- DomainSalience

造成“双重加成”。

### 随心体验派

它是风格，不是领域。

暂定：

```text
A13=A → StyleSalience=100
A13=B → 85
未触发A13但人格已确认 → 75
A13=C → 50
A13=D → 30
```

后续真实样本再校准。

## 4.6 修正后重跑 T20

### 原算法

```text
日课打卡派 Main ≈ 95.0
本命真爱党 Main ≈ 85.3
```

原因：

> P5=3 只是更高频，却被当成“更重要”。

### 新算法示例

假设 M01：

```text
M1 角色 = 100
M5 长期经营 = 70
```

则：

```text
本命真爱党 Main ≈ 90.3
日课打卡派 Main ≈ 89.0
```

主人格恢复为：

> **本命真爱党**

而：

> 日课打卡派

继续作为高共鸣人格。

**决策：采纳。**

# FIX-02｜新增 P_raw 与 P_effective

## 5.1 不再直接覆盖 Gate 原回答

后台同时保存：

```text
P_raw
P_effective
```

### P_raw

用户在 Gate 中的原始自评。

### P_effective

结合后续真实行为证据后的“当前有效参与度”。

---

## 5.2 恢复规则 v0.3.1

### Level 0｜不恢复

```text
只有1条弱证据
```

保持：

```text
P_effective = P_raw
```

相关标签仍可以触发。

### Level 1｜部分恢复

```text
1条明确强事实
或
2条中等行为证据
```

追加验证题后若成立：

```text
P_effective >= 1
```

### Level 2｜强恢复

满足：

```text
至少2条来自不同题的强参与证据
+
1条领域验证题达到强/中强参与
```

则：

```text
P_effective = max(P_raw, 2)
```

### Level 3｜极强恢复

存在多个持续事实，例如：

- 多个高难/配队行为
- 长期并行维护多游
- 长期高社区参与

可以：

```text
P_effective = 3
```

但必须至少有：

```text
1条明确长期事实
+
2条不同题强证据
```

---

## 5.3 Hard Gate 一律读取 P_effective

例如：

```text
高难工程师：
P3_effective >= 2
```

不再只看：

```text
G03 原始答案
```

---

## 5.4 修正 T18

原始：

```text
G03 → P3_raw=0
```

后续：

- 极限低配通关
- 高难差一档愿意反复凹
- 高难验证题继续表现出挑战欲

则：

```text
P3_effective=2
```

高难工程师重新获得候选资格。

**决策：采纳。**

# FIX-03｜强度经理人增加“直接角色决策 Gate”

## 6.1 问题

T06“高难 + 配队双修玩家”出现：

```text
强度经理人 Fit ≈ 71.4
```

但该画像的核心其实只是：

- 高钻研
- 高挑战
- 比较看重实战

并不代表：

> 抽角色时真的以强度价值为主要决策标准。

当前公式：

```text
D1- 45%
S3  40%
D5+ 15%
```

可能让：

> 高 D5 + 中高 S3

把人格推过 70。

# 23. P0.5 最终判断

> **现有 24 人格架构可以继续，不需要因为这轮推演推倒重来。**

真正发现的问题主要集中在：

```text
“参与多少”
和
“最在意什么”
之前混在了一起；

以及
Gate恢复后的强行为没有获得足够的反向纠错能力。
```

修正 P/M 与 P_raw/P_effective 后，系统结构明显更稳。

本轮最重要的产品结论仍然是：

> **人格是否成立，与谁做 SSS 主人格，是两件不同的事。**

> **重度玩家可以同时拥有很多成立人格；轻度玩家也可以只拥有一个。**

> **自适应测试的目的不是让每个人做更少的题，而是把题目问在真正需要区分的地方。**
