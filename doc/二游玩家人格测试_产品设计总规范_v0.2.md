# 二游玩家人格测试｜产品设计总规范 v0.2

> 项目定位：面向公开发布的二游玩家人格测试 / 人格档案产品  
> 核心目标：**先做到“测得准、讲得清、愿意分享”，再追求题量整齐、人格分布均匀或视觉上的形式统一。**  
> 视觉母题：**二游抽卡 × 人格档案馆 × SSS 金色角色揭晓**  
> 结果体系：**1 个 SSS 主人格（24常规人格或隐藏档案） + 0～N 个共鸣人格 + 0～N 个行为标签 + 8 维光谱（含证据状态）**

---

# 1. 项目核心定位

这不是简单把 MBTI 换成“二游皮肤”，也不是把玩家强行切成 24 个互斥格子。

更合适的定义是：

> **用一组稳定维度描述“你是怎么当一个二游玩家的”，再识别出你身上最鲜明的玩家原型，并用角色化、抽卡化、档案化的方式展示出来。**

整个产品应同时满足三件事：

1. **准确性**：玩家能理解“为什么我会测出这个结果”。
2. **识别性**：人格名和视觉一眼就能看懂。
3. **传播性**：结果页、分享卡、标签有足够的梗和社交表达价值。

推荐产品心智：

```text
不是：
“你被分到了哪个格子”

而是：
“系统从你的回答中识别出了哪些稳定玩家模式，
其中最鲜明的一种成为你的 SSS 主人格”
```

---

# 2. 最重要的设计原则

## 2.1 不追求人格人数均匀

24 个人格不需要平均分配用户。

允许出现：

```text
某人格：15%
某人格：8%
某人格：1%
某人格：0.5%
```

只要这个人格：

- 真实存在
- 有稳定行为模式
- 和其他人格有明显边界
- 能被题目可靠识别

就应该保留。

### 禁止

- 因为某人格人数太少而人为放宽判定
- 因为某人格人数太多而人为降低出现概率
- 为了让 24 人格“看起来漂亮”而硬平衡分布

统计数据只用于检查：

> **题目是不是设计错了？人格边界是不是不成立？**

而不是用来决定：

> “这个人格发得太多了，压一点。”

---

## 2.2 人格不是完全互斥分类，而是玩家原型

一个玩家完全可能同时明显符合：

- 本命真爱党
- 高难工程师
- 主游定居派
- 攻略课代表

这四者分别描述：

- 角色关系
- 战斗方式
- 游戏归属
- 社区行为

它们并不冲突。

因此：

```text
24 人格分别计算“证据是否成立”
而不是：
24 人格互相排他，最后只能有一个成立
```

### 最终展示

- **SSS 主人格**：固定 1 个
- **共鸣人格**：0～N 个
- **行为标签**：0～N 个

---

## 2.3 不严格限制共鸣人格和标签数量

重度玩家可能同时符合很多人格和标签。

例如：

```text
SSS 主人格
配队建筑师

共鸣人格
高难工程师
本命雕刻师
卡池规划师
攻略课代表
全收集派

行为标签
机制研究员
极限配队师
宝箱清扫队
全勤打卡官
摄影师
萌新引路人
前瞻情报员
屯屯鼠
……
```

轻度玩家也可能只有：

```text
SSS 主人格
剧情深潜员

共鸣人格
无

行为标签
同人巡礼者
```

两种结果都应该视为正常。

### 原则

> **控制证据质量，不控制结果数量。**

UI 可以控制首屏展示数量，但完整人格档案应允许展示所有满足条件的结果。

---

## 2.4 行为数量不等于人格强度

重度玩家可能：

- 剧情全看
- 地图 100%
- 高难打满
- 本命满配
- 每日全勤
- 社区高强度
- 同时玩三四款二游

不能因为“做得多”就让所有人格一起高分。

人格更应该测：

> **为什么做、怎么做、遇到冲突时优先什么。**

例如两个玩家都 100% 探索：

### 玩家 A

> 因为喜欢乱逛、发现风景。

→ 更像 **自由探索家**

### 玩家 B

> 因为无法接受地图显示 97%。

→ 更像 **全收集派**

参与强度相同，但人格不同。

---

# 3. 当前人格体系应该怎么理解

## 3.1 不是 24 个互斥“心理类型”

更合理的表述：

> **24 种二游玩家原型。**

它们可以共存，只是强弱不同。

### 角色域

- 本命真爱党
- 版本心动派
- 全员心动派
- 白月光守护者
- 强度经理人
- 本命雕刻师
- 卡池规划师

### 内容 / 战斗域

- 世界观考古学家
- 剧情深潜员
- 高难工程师
- 配队建筑师
- 随心体验派
- 自由探索家
- 全收集派

### 游戏生命周期域

- 主游定居派
- 日课打卡派
- 版本活动特种兵
- 版本候鸟
- 二游排班师

### 社区 / 全局域

- 独享小宇宙
- 同好召集人
- 攻略课代表
- 节奏免疫体
- 多面体验派

> 注：24 人格名称仍可继续做最后一轮语言校准，但不建议再为了“对称”“均匀”去改人格结构。

# 4. 人格名称设计原则

正式人格名优先满足：

1. **一眼看懂**
2. **褒义或中性**
3. **没有明显贬损、嘲讽或阵营敌意**
4. **和其他人格有清楚差异**
5. **方便视觉化**
6. **玩家愿意把它作为自己的公开标签**

例如：

- 本命钉子户 → **本命真爱党**
- 性能经理人 → **强度经理人**
- 日课公务员 → **日课打卡派**
- 多游时间管理师 → **二游排班师**
- 攻略传教士 → **攻略课代表**
- 社区观察员 → **吃瓜观察员**（更适合标签层）
- 深渊工程师 → **高难工程师**

### 不再保留“旧名作为彩蛋称号”

人格名字一旦改，就彻底改。

---

# 5. 人格和标签必须分层

## 5.1 人格

人格必须满足：

- 稳定
- 跨多个场景
- 有多条独立证据
- 有明确边界
- 与其他人格可区分

不能靠单题决定。

---

## 5.2 标签 / 称号

标签允许非常具体、非常极端、非常有梗。

有些甚至可以：

> **一个问题的最坚定答案直接触发。**

例如：

| 行为 | 标签 |
|---|---|
| 只抽强势角色 | 强度先遣队 |
| 更看角色外观、人设 | XP鉴赏家 |
| 只抽男性角色 | 男角色收藏家 |
| 只抽女性角色 | 女角色收藏家 |

| 喜欢抄作业、省时间 | 作业速通员 |
| 喜欢探索地图 | 地图开荒官 |
| 宝箱一个都不想漏 | 宝箱清扫队 |
| 经常跳剧情 | 剧情速通侠 |
| 喜欢看角色关系、CP | 关系观察员 |
| 喜欢研究设定细节 | 设定考古学家 |
| 喜欢拍照 | 摄影师 |
| 喜欢家园系统 | 家园建筑师 |
| 喜欢收集角色 | 图鉴收藏家 |
| 喜欢收集武器/皮肤 | 限定收藏官 |
| 什么资源都舍不得用 | 屯屯鼠 |
| 一有资源马上用 | 资源行动派 |
| 有多少抽多少 | 抽卡行动派 |
| 经常等复刻 | 复刻守望者 |

| 喜欢看二创 | 同人巡礼者 |

| 喜欢低配通关 | 极限配队师 |
| 喜欢整活阵容 | 配队实验家 |

| 同时玩很多二游 | 多宇宙旅行者 |
| 新游戏都尝鲜 | 新游侦察兵 |
| 经常开服入坑 | 开服先遣队 |
| 经常退坑又回来 | 回坑候鸟 |

# 6. 24 人格必须有明确边界

最容易混淆的人格必须用“核心问题”拆开。

## 本命真爱党 vs 白月光守护者 vs 本命雕刻师

```text
本命真爱党
→ 现在谁最重要？
→ 核心席位是否高度集中

白月光守护者
→ 喜欢能持续多久？
→ 很久以前的喜欢是否仍被保留

本命雕刻师
→ 愿意为核心角色投入多深？
→ 是否追求纵向养成极致
```

---

## 版本心动派 vs 全员心动派

```text
版本心动派
→ 时间轴上的追新
→ 每个版本容易出现新的情感中心

全员心动派
→ 同一时间的喜欢容量大
→ 不需要选唯一
```

---

## 强度经理人 vs 卡池规划师

```text
强度经理人
→ 这个角色值不值得抽？

卡池规划师
→ 即使值得，现在是不是应该抽？
```

---

## 强度经理人 vs 配队建筑师 vs 高难工程师

```text
强度经理人
→ 抽谁更值

配队建筑师
→ 怎么组更有意思、更成体系

高难工程师
→ 怎么打过、怎么打得更好
```

---

## 世界观考古学家 vs 剧情深潜员 vs 自由探索家

```text
世界观考古学家
→ 信息沉浸
→ 我想弄清这个世界为什么是这样

剧情深潜员
→ 情绪沉浸
→ 我想经历人物和故事

自由探索家
→ 空间沉浸
→ 我想亲自走进这个世界看看
```

---

## 独享小宇宙 vs 节奏免疫体

```text
独享小宇宙
→ 我本身就不太需要社区

节奏免疫体
→ 我会看社区，但很少让社区替我做判断
```

因此：

> 完全不看社区的人，不能判成节奏免疫体。

---

## 版本候鸟 vs 二游排班师

```text
版本候鸟
→ 不同版本之间迁徙主场

二游排班师
→ 同一时间长期维护多个游戏
```

---

## 自由探索家 vs 全收集派

```text
自由探索家
→ 享受发现过程

全收集派
→ 追求完成闭环
```

97% 探索时：

- “自己找不到就算了” → 自由探索家
- “都 97% 了必须补到 100%” → 全收集派

---

# 7. 题库不应该是纯固定题，也不应该是纯决策树

最合理的结构：

> **固定核心题 + 参与度 Gate + 自适应分流题 + 必要时终局鉴别题**

---

# 8. P + D + S + Gate 测量模型

## 8.1 P：参与度

P 只回答：

> 这个领域对用户是否真实适用？

建议：

| 编号 | 领域 |
|---|---|
| P1 | 角色 / 抽卡 / 养成 |
| P2 | 剧情 / 世界观 |
| P3 | 战斗 / 高难 / 配队 |
| P4 | 探索 / 收集 |
| P5 | 日常 / 资源经营 |
| P6 | 社区 / 二创 / 联机 |
| P7 | 多游 / 新游 / 版本迁徙 |

P 建议内部四级：

```text
0 = 基本不参与
1 = 偶尔参与
2 = 经常参与
3 = 核心玩法 / 高参与
```

---

## 8.2 D：8 个稳定光谱

保留 8 维：

| 维度 | A 端 | B 端 | 核心问题 |
|---|---|---|---|
| D1 角色价值 | 羁绊导向 | 强度导向 | 一个角色为什么值得我拥有？ |
| D2 角色集中度 | 本命集中 | 多角博爱 | 我的喜欢集中还是分散？ |
| D3 情感持续性 | 长情 | 追新 | 喜欢形成后会不会长期维持？ |
| D4 世界沉浸 | 入戏沉浸 | 玩法聚焦 | 虚构世界本身是不是重要体验？ |
| D5 掌控需求 | 钻研精通 | 随适体验 | 我有多想把游戏玩明白？ |
| D6 游戏归属 | 主驻 | 轮游 | 我长期住一个游戏还是多游流动？ |
| D7 游戏节律 | 习惯常驻 | 事件驱动 | 稳定日常还是版本驱动？ |
| D8 社群取向 | 自洽独享 | 同好共振 | 快乐主要自己完成还是需要共同参与？ |

---

## 8.3 S：行为子信号

用于拆开共享同一 D 维度的人格。

推荐：

| 编号 | 子信号 |
|---|---|
| S1 | 角色情感深度 |
| S2 | 收藏完成欲 |
| S3 | 强度效率欲 |
| S4 | 纵向养成欲 |
| S5 | 体系构筑欲 |
| S6 | 高难挑战欲 |
| S7 | 剧情情绪投入 |
| S8 | 设定求知欲 |
| S9 | 空间探索欲 |
| S10 | 资源规划欲 |
| S11 | 规律维护欲 |
| S12 | 社区消费量 |
| S13 | 主动表达欲 |
| S14 | 教学助人欲 |
| S15 | 独立判断度 |
| S16 | 新内容敏感度 |

这些不用在结果页全部展示。

它们主要服务后台人格判定。

---

## 8.4 Gate：人格门控

每个人格应具备：

### Hard Gate

定义型必要条件。

例如：

> 二游排班师  
> 必须长期同时维护至少 2 款二游。

---

### Soft Gate

强支持条件。

不满足时不一定直接淘汰，但人格证据下降。

---

### Contradiction

明显与人格核心矛盾的信号。

---

### Discriminator

当两个人格难分时才追加的专属鉴别题。

---

# 9. 一个答案能不能排除很多人格？

可以，但必须区分情况。

## 可以大幅淘汰的情况

### 1. 明确事实型必要条件

例如：

> “我基本长期只玩一个游戏。”

则：

- 二游排班师直接退出主人格候选

### 2. 多道一致强证据

可以对若干候选人格做大幅降权。

### 3. 标签触发

一个坚定回答就可以定标签。

---

## 不应该大规模淘汰的情况

### 单个普通情境题

不能因为一次回答就判断：

> “你绝不可能是某人格。”

因为它可能受：

- 当前版本
- 最近是否忙
- 某款游戏设计
- 具体角色
- 当时心情

影响。

---

# 10. “不适用”必须正式加入

原题库最大结构问题之一：

> 每个人都必须在每题的 A/B/C/D 中选一个。

这会给轻度玩家制造假信号。

例如一个完全不打高难的玩家，不应该被迫回答：

> “高难打不过时是继续研究还是随适？”

他最真实的答案是：

> **这类情况对我基本不适用。**

因此部分题允许：

```text
E. 这类情况对我基本不适用
```

E：

- 不进入 D 维度方向分
- 不按 50:50 处理
- 记录参与度不足
- 可触发后续跳题

---

# 11. 8 维光谱仍然适用，但必须升级

8 维依然值得保留。

因为它：

- 提供稳定连续属性
- 可以解释主人格
- 给结果页增加“人格档案感”
- 不需要把所有人硬切成极端类型

但不能只展示一个百分比。

必须同时展示：

> **倾向位置 + 证据状态**

例如：

```text
角色价值
羁绊导向 ━━━━━━━●━━ 强度导向
证据：高
```

轻度玩家：

```text
掌控需求
钻研精通 ━━━?━━━━━━ 随适体验
证据：较少
相关玩法参与较少，暂不足以判断稳定倾向
```

### 重点

> **50:50 ≠ 没有参与。**

50:50 表示：

> 有足够证据，但两端较平衡。

“不适用”表示：

> 没有足够信息。

二者必须分开。

# 12. 自适应题库结构

建议：

```text
阶段 1

阶段 2

阶段 3
计算 24 人格候选

阶段 4
若候选接近：
追加 1～6 道高信息量专属鉴别题

阶段 5
必要时补标签题

阶段 6
生成结果
```

# 13. 推荐题量

成熟版本：

| 玩家类型 | 预计题量 |
|---|---:|
| 兴趣非常集中 / 轻度玩家 | 24～30 |
| 普通玩家 | 30～36 |
| 重度、多领域玩家 | 34～42 |
| 候选高度接近 | 最多约 44 |

不追求人人题量一致。

---

# 14. 为什么不能直接做纯决策树

因为 24 人格不是严格互斥。

例如：

> “喜欢本命”

不能排除：

> “高难工程师”

两者完全可以同时存在。

所以真正适合树状分流的是：

> **同一竞争组内部。**

例如：

```text
本命真爱党
vs
白月光守护者
vs
本命雕刻师
```

或者：

```text
版本候鸟
vs
二游排班师
```

---

# 15. 自适应测试的核心是“信息增益”

系统不应该只问：

> 谁现在分最高？

而应该问：

> **下一题问什么，最能区分目前仍然成立的几个候选人格？**

例如当前：

```text
本命真爱党       很高
白月光守护者     很高
本命雕刻师       很高
其他人格         明显较低
```

下一题应该优先问：

- 本命 vs 白月光
- 本命雕刻 vs 普通本命

而不是再去问：

> “你看不看社区？”

---

# 16. 结果页文案原则

## 16.1 结果要解释“为什么是你”

不能只有：

```text
SSS
本命真爱党
匹配度 92%
```

必须进一步解释：

- 你哪些回答最有代表性
- 这些回答说明什么
- 为什么它比其他人格更突出

推荐结构：

```text
SSS 主人格
↓
人格一句话
↓
高光特质
↓
为什么你会测出这个人格
↓
3～5 条代表性回答证据
↓
8 维光谱
↓
共鸣人格
↓
全部标签
↓
心理学 / 行为机制解释
↓
与你反差较大的体验方式
↓
分享卡
```

---

## 16.2 用“高光特质”，不要用缺陷描述

不要：

> 你不爱研究。

改成：

> 你更珍惜轻松、流畅的体验。

不要：

> 你容易被新角色诱惑。

改成：

> 你对新角色和新内容拥有很高的情感响应速度。

不要：

> 你不在乎社区。

改成：

> 你的游戏快乐主要能在自身体验中闭环。

---

# 17. 不使用“你最难理解的玩家”

结果页避免：

- 你最讨厌的玩家
- 你最难理解的人
- 你最容易和谁吵起来
- 哪类人和你最不合

推荐：

## 标题

> **与你反差较大的体验方式**

或者：

> **另一种游戏乐趣**

示例：

> 你更容易从角色关系本身获得满足，而强度经理人更享受资源配置、阵容效率和版本规划。你们关注的奖励来源不同，但都在认真经营自己的游戏体验。

还可以增加：

> **你可能会欣赏他们：**  
> 在有限资源中做出清晰取舍的能力。

目标：

> **描述差异，不制造阵营敌意。**

---

# 18. 心理学解释可以加入，但必须克制

心理学应该：

> **解释已经测到的行为**

而不是：

> 给结果强行“镀科学金边”。

适合使用的方向包括：

- 自主感
- 胜任感
- 联结感
- 习惯形成
- 熟悉效应
- 延迟满足
- 完成倾向
- 信息探索
- 社会认同
- 独立判断

---

## 18.1 示例：日课打卡派

不要写：

> 你每天机械打卡。

推荐：

> 你很擅长建立稳定的游戏节律。  
> 当上线、清体力、做日常逐渐嵌入固定生活场景后，很多操作不再需要每次重新做决定。你实际上是在用稳定节律降低启动成本。

---

## 18.2 示例：高难工程师

推荐：

> 你获得乐趣的一种重要方式，是把“不知道怎么解决”一步步变成“我已经弄明白了”。复杂机制和高难挑战对你来说，不只是门槛，也是获得掌控感和成长反馈的来源。

---

## 18.3 示例：同好召集人

推荐：

> 你擅长把一个人的喜欢变成一群人的快乐。对你来说，“有人也懂这个角色为什么好”本身就是游戏体验的一部分。

---

## 18.4 不要过度推断现实人格

错误：

> 因为你喜欢研究配队，所以你现实中逻辑能力极强。

推荐：

> 在游戏场景中，你表现出明显的结构化思考倾向。

测试测的是：

> **二游行为与偏好**

不是完整人格、职业能力或现实性格诊断。

---

# 19. “夸玩家”的正确方式

可以尽量正向，但不能无脑吹。

最有效的夸法是：

> **指出具体能力 + 给出行为证据。**

例如：

### 卡池规划师

> 你很擅长把短期心动和长期目标分开处理。  
> 当资源有限时，你不会只看“现在想不想抽”，还会把未来目标、保底和复刻一起纳入决策。

### 本命真爱党

> 你的喜欢不是短期注意力，而是具有明显的稳定性和核心席位感。真正进入你核心名单的角色，通常不会轻易被版本更新覆盖。

---

# 20. 全 SSS 金色结果的规则

所有人格统一：

> **SSS 金色人格 / SSS 金色角色**

没有低级人格。

因此不应该使用：

- 检测到特殊人格
- Exceptional Archive
- 超稀有
- 你抽到了比别人更高级的人格

因为人人都是 SSS。

抽卡悬念应该是：

> **“我会抽到谁？”**

而不是：

> **“我是不是出金？”**

推荐系统文案：

```text
人格档案同步完成
PRIMARY ARCHIVE
SSS
```

或者：

```text
核心人格已锁定
SIGNATURE PROFILE
SSS
```

---

# 21. 避免虚假精确度

不要使用：

```text
MATCH COMPLETE 99.97%
人格匹配率 92.36%
```

尤其在没有真实统计校准前。

这种精确数字很容易产生伪科学感。

推荐：

- 高度匹配
- 核心人格已锁定
- 主要信号一致
- 8/8 档案信号同步完成
- 高共鸣 / 明显共鸣 / 次级共鸣

如果以后做“匹配指数”，也应明确它是：

> **产品内部标准化指数**

而不是心理学概率或统计置信度。

# 22. 结果页 8 维视觉建议

雷达图可以保留，但更适合：

> 装饰 / 科技感

真正用于理解的部分，建议使用：

> **双端光谱条**

例如：

```text
角色价值
羁绊导向  ━━━━━━━●━━  强度导向

角色集中
本命集中  ━━━━━●━━━━  多角博爱
```

并增加：

```text
证据：高 / 中 / 较少
```

24 个人格如果都使用大尺寸透明图，移动端容易卡顿。

- 避免首屏加载过多视频素材

# 32. 数据校准路线

人格体系目前仍然属于：

> **理论原型池 + 产品设计稿**

正式公开前应经过真实样本校准。

## 第一阶段：20～30 人认知访谈

重点不是只问：

> “准不准？”

还要问：

- 哪道题很难选？
- 哪道题完全不适用？
- 哪两个选项感觉是同一件事？
- 哪道题让你觉得在“猜测试答案”？
- 哪个人格名看不懂？
- 哪个人格结果你认为和另一个太像？

---

## 第二阶段：300～500 份有效答卷

重点检查：

- 同维度题是否真的同向
- Gate 是否误杀
- 某题是否 90% 都选一边
- 某人格是否几乎没人能触发
- 某两个人格是否总一起出现
- 哪些专属鉴别题区分度最高

---

## 第三阶段：1000+ 样本

再考虑：

- 缩短固定题数量
- 扩大自适应跳题
- 调整 Hard Gate
- 调整人格权重
- 删除低信息量题
- 合并或重定义无法区分的人格

---

# 33. 人格判定规则建议

不建议：

```text
8维坐标
→ 与24个中心统一计算欧氏距离
→ 最近的就是主人格
```

推荐：

```text
人格证据 =
核心维度匹配
+ 关键子信号匹配
+ 专属鉴别信号
- 矛盾惩罚
```

并且先经过：

> Hard Gate

---

## 33.1 最低证据要求

一个人格要正式展示，建议至少：

- 3 个独立回答支持
- 至少 1 个来自核心题
- 至少 1 个来自不同情境
- 没有定义性矛盾

标签则可以更宽松。

---

# 34. 结果数量规则

## 主人格

固定：

> **1 个**

## 共鸣人格

满足证据门槛的全部：

> **0～N**

## 行为标签

满足触发条件的全部：

> **0～N**

不要规定：

> “必须 2 个副人格、5 个标签。”

---

# 35. 多面体验派必须防止变成“垃圾桶人格”

多面体验派不能表示：

> “其他 23 个都不像，所以给你这个。”

它必须有自己的 Hard Gate：

- 多个领域真实参与
- 至少 4 个 P 领域达到中高
- 多种快乐来源都稳定存在
- 没有单一动机压倒性支配

它描述的是：

> **真正的多元体验结构**

而不是：

> **测不出来。**

---

# 36. 轻度玩家也必须能被准确描述

例如一个玩家：

- 主要过剧情
- 不打高难
- 不研究配队
- 不怎么社区
- 不做 100% 探索

结果完全可以是：

```text
SSS 主人格
剧情深潜员

共鸣人格
无

标签
同人巡礼者
```

不要为了页面“丰富”强行给他：

- 高难人格
- 社区人格
- 探索人格

---

# 37. 重度玩家也不要被压缩成一个标签

重度玩家可能真的同时具有：

- 强构筑
- 强挑战
- 强收集
- 强规划
- 强社区
- 强角色投入

这时共鸣人格越多反而越真实。

产品应该允许用户展开：

> **完整人格档案**

去看全部满足条件的原型。

# 39. 文案最终总原则

整套产品文字应坚持：

## 39.1 描述偏好，不描述缺陷

不是：

> 你没有耐心研究。

而是：

> 你更重视顺畅、舒服的游玩体验。

---

## 39.2 描述差异，不制造阵营

不是：

> 你最看不懂强度党。

而是：

> 和你反差较大的体验方式是“强度经理人”。

---

## 39.3 夸具体能力，不做空洞奉承

不是：

> 你真的很厉害。

而是：

> 你很擅长把长期资源目标和短期抽卡冲动分开处理。

---

## 39.4 科学解释只解释行为，不越界诊断

不是：

> 你现实中就是高逻辑型人格。

而是：

> 在游戏场景中，你表现出明显的结构化思考倾向。

# 40. 产品最终目标

这个项目最理想的用户反馈不是：

> “动画好帅。”

也不只是：

> “角色好可爱。”

而应该是三层递进：

```text
第一层：
“这题也太像我平时玩的情况了。”

第二层：
“原来我这些习惯背后真有一个稳定模式。”

第三层：
“这个结果怎么这么像我，我要发给朋友看。”
```

因此整个项目的优先级应始终是：

```text
1. 人格边界
2. 题目有效性
3. 判定规则
4. 结果解释
5. 名称与文案
6. 分享传播
7. 抽卡动画和视觉包装
```

# 42. 一句话产品原则

> **8维负责描述稳定倾向，参与度负责判断哪些问题适用，行为子信号负责拉开人格边界，Gate 防止明显误判，自适应鉴别题解决最后的模糊，共鸣人格和标签负责让玩家看到更完整的自己。**

> **不为了均匀分布设计人格，不为了页面整齐限制结果数量，不为了科学感制造虚假精确度。**

> **最终目标不是把玩家塞进 24 个格子，而是让每一种真实存在的二游玩家，都能在“二游人格档案”里找到自己的位置。**

# 43. v0.2 判定体系冻结更新

## 43.1 24常规人格核心定义冻结

从本版开始，24个常规人格的核心定义不再随意改动。

后续允许：

- 名称轻微措辞优化
- 人格结果文案优化
- 视觉道具和动作优化
- 真实数据后调整阈值和题目权重

不再为了“分布更均匀”“结构更对称”而修改人格内核。

---

## 43.2 新增隐藏档案：二游观察者

新增：

> **SSS｜二游观察者**

但它不是普通第25人格，而是**真实低参与关系的隐藏结果**。

核心语义：

> 你和二游保持一种比较轻盈的距离。真正感兴趣时会靠近角色、剧情、新版本或朋友讨论，但并不需要通过清日常、凹高难、清地图、追全收集来维持身份感。

它只用于：

> **真实低参与**

绝不用于：

> **数据不足 / 回答矛盾 / 测量失败**

后者继续使用后台 `LOW_EVIDENCE` 状态并补题。

---

## 43.3 新增 M 动机中心性

正式区分：

```text
P：实际参与多少
M：哪些体验真正不能缺
```

这样可以避免：

> “每天做日课”自动把用户判成“日课打卡派主人格”。

M01 使用：

> **1～3项多选，不排序**

降低用户操作复杂度。
