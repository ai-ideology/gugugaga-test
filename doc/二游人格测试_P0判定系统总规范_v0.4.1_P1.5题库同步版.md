# 0. P0 本轮结论

本轮正式把系统从：

```text
回答题目 → 8维分数 → 找最近人格
```

升级为：

```text
P_raw / P_effective 参与度与适用性
        +
D 8维连续倾向
        +
S 行为子信号
        +
F 派生事实特征
        +
M 7类动机中心性
        +
人格 Hard Gate / Contradiction
        +
A 自适应鉴别题
        ↓
24个常规人格分别计算“成立证据”
        ↓
确认 0～N 个成立人格
        ↓
若真实低参与且无常规人格成立
→ 隐藏档案 H01「二游观察者」
        ↓
常规人格成立时：
MainIndex 中心性比较
        ↓
必要时追加跨领域终局取舍题 MX
        ↓
固定 1 个 SSS 主人格
+ 0～N 共鸣人格
+ 0～N 标签
```

核心原则仍然是：

> **控制证据质量，不控制结果数量。**

# 1. 本轮新增的两个必要结构

## 1.1 新增 S17｜体验自主度

原有 D5「钻研精通 ←→ 随适体验」不足以区分：

- 真正的“随心体验派”
- 只是几乎不参与高难/构筑的轻度玩家

因此新增后台子信号：

> **S17 体验自主度**：当奖励、完成度、最优解与个人舒适体验冲突时，用户是否能自然选择“够用就好 / 不必证明 / 不必清满”。

它不出现在结果页 8 维中，只用于人格识别。

---

## 1.2 新增 MX｜跨领域主人格终局取舍题

重度玩家可能在角色、剧情、战斗、收集、社区等领域全部高参与、全部高证据。

这种情况下，单靠“哪个人格 Fit 更高”不一定能决定：

> **哪个人格最能代表“我为什么长期玩二游”。**

因此新增动态终局题模板，仅当跨领域前两名主人格指数过近时出现。

### MX 模板

> 如果未来一款二游只能保留下面两种体验中的一种，哪一种更能成为你继续玩的理由？
>
> A. `{候选人格A对应的核心体验}`  
> B. 两者都很重要，但 A 略重要  
> C. 两者都很重要，但 B 略重要  
> D. `{候选人格B对应的核心体验}`

MX **不改变人格是否成立**，只改变“谁做 SSS 主人格”的中心性权重。

# 2. 数据层定义

## 2.1 P｜参与度 / 适用性

| 编号 | 领域 |
|---|---|
| P1 | 角色 / 抽卡 / 养成 |
| P2 | 剧情 / 世界观 |
| P3 | 战斗 / 高难 / 配队 |
| P4 | 探索 / 收集 |
| P5 | 日常 / 资源经营 |
| P6 | 社区 / 二创 / 联机 |
| P7 | 多游 / 新游 / 版本迁徙 |

Gate 题：

```text
A = 3
B = 2
C = 1
D = 0
```

P 只负责：

- 题目是否适用
- 跳题与恢复
- Hard Gate 的参与前提

**P 不再直接作为主人格中心性。**

正式保存：

```text
P_raw       = Gate 初始自评
P_effective = 后续行为证据修正后的有效参与度
```

Hard Gate 和正式跳题读取 `P_effective`。

---

## 2.2 M｜7类动机中心性

M 只用于多个成立人格之间选择 SSS 主人格。

| 编号 | 核心乐趣 |
|---|---|
| M1 | 角色 / 抽卡 / 养成 |
| M2 | 剧情 / 世界观 |
| M3 | 战斗 / 高难 / 配队 |
| M4 | 探索 / 收集 |
| M5 | 长期经营 / 日常 / 资源 |
| M6 | 社区 / 二创 / 联机 |
| M7 | 新版本 / 新游 / 迁徙 |

来源：M01 多选题。

M01 允许选择 1～3 项，不排序；若确实没有任何“不能缺”的核心乐趣，可选择互斥项 H：

```text
被选中 = 100
未选中且 P_effective>=2 = 55
未选中且 P_effective=1 = 35
未选中且 P_effective=0 = 20

H = 不设置任何 M=100，所有 M 仅按 P_effective 基础值计算
```

它回答的是：

> **“什么是我玩二游最不能缺的体验？”**

而不是：

> “我每天花时间最多做什么？”

## 2.3 D｜8维连续光谱

后台统一方向：

| 维度 | + 方向 | - 方向 |
|---|---|---|
| D1 | 羁绊导向 | 强度导向 |
| D2 | 本命集中 | 多角博爱 |
| D3 | 长情 | 追新 |
| D4 | 入戏沉浸 | 玩法聚焦 |
| D5 | 钻研精通 | 随适体验 |
| D6 | 主驻 | 轮游 |
| D7 | 习惯常驻 | 事件驱动 |
| D8 | 自洽独享 | 同好共振 |

核心题默认：

```text
A = +2
B = +1
C = -1
D = -2
E = null / 不适用
```

### 标准化

设有效回答分值为 `r_i`，题权重为 `w_i`：

```text
D_z = Σ(w_i × r_i) / Σ(w_i × 2)
```

所以：

```text
D_z ∈ [-1, 1]
```

结果页 A 端位置：

```text
D_A_pct = 50 + 50 × D_z
D_B_pct = 100 - D_A_pct
```

E 不进入分母。

# 3. 不同题型的权重

| 题型 | 用途 | 后台权重 |
|---|---|---:|
| G Gate题 | P / 适用性 | 1.0 |
| C 核心情境题 | D + S | 1.0 |
| A 人格鉴别题 | 专属人格鉴别 + S | 1.25 |
| T 标签题 | 标签为主；可提供弱人格证据 | 0.5 |
| MX 终局中心性题 | 仅主人格选择 | 不进入 Fit |

### 重要决策

标签题往往比较直白，例如“你是否经常帮助萌新”。

因此：

> **标签可以直接触发，但标签题用于人格判定时只按 0.5 权重。**

防止用户直接自我贴标签对人格结果影响过大。

# 4. 派生事实特征 F

有些人格不是单一 D/S 能表达，需要从多个回答派生事实量。

## F1｜ConcurrentMulti 多游并行度

用于二游排班师。

主要证据：

- G07 多游参与
- A10 是否同时推进多个游戏
- T22 是否长期同时维护多款二游

归一化 0～100。

## F1.1｜F1 可执行计算

将多游并行证据映射为 0～100：

```text
G07: A=100, B=70, C=30, D=0
A10: A=0,   B=25, C=75, D=100
T22: 勾选“同时长期维护多款二游”=100；未勾选=0
```

若三项都存在：

```text
F1 = 0.30×G07 + 0.40×A10 + 0.30×T22并行事实
```

若 A10 尚未触发，则只对已有项重新归一化；但二游排班师在没有直接并行事实前不能通过 Hard Gate。

---

## F2｜CrossCollection 跨系统收集度

用于全收集派。

统计以下不同系统是否出现“明显收齐 / 完成”倾向：

- 角色
- 武器 / 装备
- 皮肤 / 限定物
- 地图 / 宝箱
- 成就 / 图鉴
- 家园 / 收藏品

至少 2 个独立系统成立，Hard Gate 才通过。

### F2 当前的覆盖限制

现有题库可以较好识别“地图/宝箱完成”和“角色/装备/皮肤收藏”，但对“多个系统都追求收齐”仍不够强。

因此 v0.3 暂定：

```text
StrongSystem = 某系统同时存在“收藏对象” + “明确补完/不愿留空”的证据
WeakSystem   = 只有收藏偏好，没有完成压力证据

F2 = min(100, 40×StrongSystem数量 + 15×WeakSystem数量)
```

全收集派 Hard Gate 暂定：

```text
StrongSystem >= 2
或 StrongSystem >=1 且 WeakSystem >=2
```

v0.4 已新增 **C25「跨系统完成欲」**。C25=A/B 可提供跨系统完成直接证据，因此 F2 不再完全依赖标签题推断。

---

## F3｜Breadth 多领域参与广度

```text
F3 = count(P_i >= 2) / 7 × 100
```

---

## F4｜Entropy 参与均衡度

令：

```text
q_i = P_i / ΣP_i
```

归一化熵：

```text
H = -Σ(q_i ln q_i) / ln(7)
F4 = H × 100
```

若 `ΣP_i = 0`，F4 记为 undefined。

F3/F4 主要用于“多面体验派”，不用于其他人格增分。

# 5. 24 人格最终判定矩阵

## 5.1 通用人格成立条件

一个人格要进入“已确认人格”，必须同时满足：

1. **Hard Gate 通过**
2. `Fit >= 70`
3. 独立证据数 `N_ind >= 3`
4. 证据质量 `EvidenceQuality >= 60`
5. 不存在定义性矛盾
6. 若该人格与主要竞争人格差距过小，完成对应 A 鉴别题

### 强确认

```text
Fit >= 80
且 EvidenceQuality >= 70
```

强确认不是“更高级人格”，只表示证据更充分。

---

## 5.2 特征兼容度

若人格要求 `D2+`：

```text
Compat(D2+) = 50 + 50 × D2_z
```

若人格要求 `D2-`：

```text
Compat(D2-) = 50 - 50 × D2_z
```

S 同理：

```text
Compat(S+) = S_pct
Compat(S-) = 100 - S_pct
```

undefined 特征不直接当 50；若属于关键特征，则降低 EvidenceQuality，必要时追加题。

---

## 5.3 BaseFit

每个人格只计算自己真正相关的特征。

```text
AvailableWeight = Σ(当前已有有效值的 feature_weight)
BaseFit_p = Σ(available_weight × feature_compatibility) / AvailableWeight
```

人格配置中的理论权重总和为 100%。

### 缺失特征规则

- **不允许把 undefined 自动补成 50。**
- `AvailableWeight >= 60%` 时可以暂算 BaseFit，但 EvidenceQuality 会因覆盖不足下降。
- `AvailableWeight < 60%` 时人格状态记为 `INSUFFICIENT_FEATURES`，不得确认，应优先追加能补关键特征的题。
- Hard Gate 所需特征无论权重多少，都不能被“其他高分”替代。

---

## 5.4 鉴别题修正

若该人格相关 A 题已回答：

```text
Fit_p = 0.80 × BaseFit_p + 0.20 × DiscScore_p
```

若没有触发 A 题：

```text
Fit_p = BaseFit_p
```

A题对目标人格的映射：

```text
强支持 = 100
弱支持 = 75
弱反对 = 25
强反对 = 0
```

多道 A 题取加权平均。

```text
T20 = A
且 D2+ 明显
且 S4 >= 70
```

不允许只凭“有本命”判成本命雕刻师。

---

## 6.3 高难工程师｜真实参与 Gate

```text
P3 >= 2
且 C13/C14 中至少2题非E
且 S6 >= 65
```

如果 G03=D，但 T21=A、C13=A 等出现两条强参与证据，则先触发“恢复规则”，不能直接判定矛盾。

---

## 6.4 二游排班师｜并行维护 Gate

以下至少一条强事实 + 一条辅助事实：

### 强事实

- T22 勾选“同时长期维护多款二游”
- A10 = C/D

### 辅助事实

- G07 = A/B
- C18 非 E 且表现多游迁移/维护
- 多个游戏日常/活动并行标签

---

## 6.5 卡池规划师｜延迟满足 Gate

至少 2 条以下证据，其中必须包含一条“为了未来目标主动跳过当前”：

- A03 = C/D
- C26 = C/D
- T13 = A/B
- T14 勾选“等复刻 / 预测卡池 / 主动看前瞻”中的计划相关项
- T12 = B

其中 `A03=C/D` 或 `C26=C/D` 至少一条必须成立。

如果 T13=D（有多少抽多少）且 A03=A/B，则构成强矛盾。

---

## 6.6 节奏免疫体｜接触后独立 Gate

必须同时满足：

```text
P6 >= 1
S12 有有效正向证据
S15 >= 70
```

完全不看社区的人只能支持“独享小宇宙”，不能支持“节奏免疫体”。

---

## 6.7 全收集派｜跨系统 Gate

必须：

```text
F2 >= 40
```

即至少 2 个不同收集系统存在明显完成倾向。

“只把一个本命练到极致”不属于全收集派。

---

## 6.8 多面体验派｜广度 Gate

必须：

```text
count(P_i >= 2) >= 4
F4 >= 78
```

且：

```text
不能因为所有P都低而进入该人格
```

多面体验派是“多种乐趣都真实重要”，不是兜底人格。

# 7. 证据质量 EvidenceQuality

人格不应只看 Fit。

定义：

```text
Coverage = min(1, N_ind / 5)
```

其中：

- 核心题 C：1 个独立证据
- 鉴别题 A：1 个独立证据
- 标签题 T：0.5 个独立证据

### 情境一致度

对人格相关证据，计算：

```text
StrongConflictRate = 强方向冲突对数量 / 可比较证据对数量
Consistency = 1 - min(0.6, StrongConflictRate)
```

最终：

```text
EvidenceQuality = 100 × (0.60 × Coverage + 0.40 × Consistency)
```

### 注意

Consistency 低不代表用户“撒谎”。

更合适的解释是：

> **这个倾向受具体游戏或场景影响较大。**

---

# 8. 主人格选择公式

一个玩家可以同时确认多个常规人格。

主人格不是“唯一成立人格”，而是：

> **最鲜明、最中心、最能代表玩家为什么长期玩二游的一个。**

## 8.1 MotivationalSalience

常规人格使用 M，而不是 P。

主要映射：

```text
本命真爱党 / 版本心动派 / 全员心动派 / 白月光 / 强度经理 / 本命雕刻 / 卡池规划
→ M1

世界观考古 / 剧情深潜
→ M2

高难工程 / 配队建筑
→ M3

自由探索
→ M4

日课打卡
→ M5

同好召集 / 节奏免疫
→ M6

版本候鸟
→ M7
```

跨域人格：

```text
主游定居派        = max(M5, M7)
版本活动特种兵    = max(M5, M7)
二游排班师        = max(M5, M7)
攻略课代表        = max(M3, M5, M6)
全收集派          = max(M1, M4, M5)
多面体验派        = 最高4个M的平均
```

随心体验派是风格人格，不强依赖单一领域：

```text
A13=A → StyleSalience=100
A13=B → 85
A13未触发但人格已确认 → 75
A13=C → 50
A13=D → 30
```

## 8.2 Distinctiveness｜同类区分度

Rival 分四类：

```text
R0 Gate Failed
→ 不进入比较

R1 Insufficient Features
→ Distinctiveness暂记50，优先补题

R2 Eligible Rival
→ Hard Gate通过且AvailableWeight>=60%，进入比较

R3 Confirmed Rival
→ 正常进入比较
```

若所有 Rival 都是 R0：

```text
Distinctiveness = 100
```

若存在 R1：

```text
Distinctiveness = 50
```

否则：

```text
Margin = Fit_p - max(Fit_rival)
Distinctiveness = clamp(50 + 5 × Margin, 0, 100)
```

## 8.3 MainIndex

只在已确认常规人格之间比较：

```text
MainIndex =
0.60 × Fit
+ 0.20 × MotivationalSalience
+ 0.10 × EvidenceQuality
+ 0.10 × Distinctiveness
```

这正式解决：

> **参与最多 ≠ 最重要。**

---

# 9. 跨领域主人格过近时：MX 终局取舍

如果：

```text
Top1 与 Top2 属于不同领域
且两者都为已确认人格
且 Fit 均 >= 70
且满足以下任一：
- MainIndex 差 < 6
- 两者 Fit 均 >= 80 且 MainIndex 差 < 10
- Top1/Top2 含“多面体验派/随心体验派”，另一人格 Fit>=80，且 MainIndex 差 < 10
```

触发 MX。

MX 只对 MainIndex 追加中心性修正：

```text
A：Top1 +8，Top2 -4
B：Top1 +4，Top2  0
C：Top1  0，Top2 +4
D：Top1 -4，Top2 +8
```

最多问 2 道 MX。

若 2 道后仍差 < 2：

依次使用：

1. Fit 更高者
2. EvidenceQuality 更高者
3. 独立证据更多者
4. 固定稳定排序作为纯技术 tie-break

第四项只解决数学完全平局，不应该成为常见规则。

---


# 9.5 隐藏档案 H01｜二游观察者

H01 不属于24个常规人格，不参与 Fit / MainIndex 正常竞争。

## 定位

> **真实低参与、低绑定的玩家关系本身，也是一种有效结果。**

它不是：

- 数据不足
- 测量失败
- 最低级人格
- “不够二游”

## 触发条件

必须同时满足：

```text
ConfirmedRegularPersonaCount = 0
count(P_effective >= 2) = 0
count(P_effective >= 1) <= 2
ΣP_effective <= 3
LowParticipationEvidenceCount >= 3
HardFactContradiction = false
```

且这些低参与证据必须来自至少3个不同领域。

## 禁止把 LOW_EVIDENCE 当成 H01

如果只是：

- 关键特征缺失
- 回答强冲突
- 跳题过多
- Gate与深度题尚未澄清

则保留：

```text
LOW_EVIDENCE
CONTEXT_SENSITIVE
INSUFFICIENT_FEATURES
```

并继续补高信息量题。

## 展示

```text
SSS
二游观察者
```

建议核心描述：

> 你和二游保持一种比较轻盈的距离。你会在真正感兴趣的时候靠近角色、故事或新内容，但不需要通过清满系统、维持日课或追求最优来证明自己的投入。

# 10. 共鸣人格展示规则

不固定副人格数量。

所有满足：

```text
已确认人格
且不是主人格
```

都可以进入“共鸣人格”。

### UI 层建议

- 首屏：最多展示最鲜明的 3～5 个
- 完整档案：展示全部
- 不因 UI 限制修改后台人格成立结果

---

# 11. 标签展示规则

标签只要触发就记录。

不设置总量上限。

但分三层：

### 强标签

极端、直接、事实型答案触发。

例如：

- T02=A → 男角色收藏家
- T03=A → 全勤打卡官
- T13=D → 抽卡行动派

### 中标签

一个主答案 + 一个侧证据。

### 弱标签

仅单个非极端答案支持，后台记录但默认不展示。

结果首屏优先展示：

1. 强标签
2. 稀有且高辨识标签
3. 与主人格互补的标签

---

# 12. 跳题规则

## 12.1 Gate 后的初始题量

### P >= 2

该领域全部核心题进入候选。

### P = 1

保留 1～2 道最高信息量核心题。

若回答出现强信号，再追加该领域剩余题。

### P = 0

跳过绝大多数深度题，但保留 1 道“交叉验证题”。

---

## 12.2 各领域 P=0 时保留的验证题

| P | 保留验证 |
|---|---|
| P1=0 | C01 + C04 + C07（分别确认 D1/D2/D3，不继续深挖） |
| P2=0 | C10 |
| P3=0 | C13 |
| P4=0 | T06 或 A07（只有出现探索候选时） |
| P5=0 | C20 |
| P6=0 | C22 |
| P7=0 | C16 |

### 为什么 P1=0 仍保留 3 题

角色价值、角色集中、情感持续是三条独立光谱。

即使用户“角色不是核心”，也可能：

- 角色少但极长情
- 不抽卡但有固定本命
- 角色关注低且完全追新

不能用一个 Gate 直接替代三个 D。

# 13. 恢复规则｜P_raw / P_effective

Gate 只做初筛。

## 13.1 Level 0｜不恢复

只有1条弱证据：

```text
P_effective = P_raw
```

## 13.2 Level 1｜部分恢复

满足：

```text
1条明确强事实
或
2条中等行为证据
```

追加验证题后成立：

```text
P_effective >= 1
```

## 13.3 Level 2｜强恢复

满足：

```text
至少2条来自不同题的强参与证据
+
1条领域验证题达到中强/强参与
```

则：

```text
P_effective = max(P_raw, 2)
```

## 13.4 Level 3｜极强恢复

存在：

```text
1条明确长期事实
+
至少2条不同题强证据
```

可：

```text
P_effective = 3
```

Hard Gate 一律读取 `P_effective`。

# 14. 自适应鉴别题触发规则

人格 A 题只在以下情况触发：

```text
两个竞争人格均通过 Hard Gate
且 BaseFit 均 >= 62
且 BaseFit 差 <= 12
```

或者：

```text
其中一个人格 Fit 很高
但关键子信号 undefined
```

### 题目优先级

优先选择预期信息增益最高的题：

1. 能直接把两个高候选分开的题
2. 能补关键 Hard Gate 的题
3. 能补关键 undefined S 的题
4. 普通重复测量题

# 15. 停止规则

## 15.1 正常停止

满足全部条件：

1. 至少 1 个已确认人格
2. 当前 MainIndex Top1 已确定
3. Top1 与 Top2：
   - 差 ≥5；或
   - 已完成必要 MX
4. 不存在未处理的 Hard Fact Contradiction
5. 所有 Top 候选关键特征都不是 undefined
6. 继续问同类题的预期信息增益低

即可停止人格测量。

---

## 15.2 最大题量停止

产品正式版建议：

```text
硬上限：44 题
```

到达上限时：

- 不再为了补标签继续问
- 优先完成主人格必要鉴别
- 标签不完整是允许的

---

## 15.3 无已确认人格的兜底

到达题量上限仍无人格达到 Fit 70：

1. 选择无 Hard Gate 冲突的人格中最高 Fit
2. 必须 `Fit >= 62`
3. 追加 1 道该人格核心验证题（即使超过普通上限 1 题）
4. 若仍无法确认，内部标记 `LOW_EVIDENCE`
5. 前台仍输出 1 个 SSS 主人格，但：
   - 不展示伪精确百分比
   - 减少共鸣人格
   - 8维对低证据项明确显示“证据较少”

**禁止把这种情况强行塞进“多面体验派”。**

# 16. 答案矛盾处理

矛盾不等于作弊。

必须先区分三种情况。

---

## 16.1 类型 A｜真实情境差异

例如：

- 高难奖励差一点时愿意凹
- 奖励全拿后不再优化

这不是矛盾，而是：

> **目标依赖型钻研。**

处理：

- 不惩罚人格
- D/S 允许呈现中间位置
- EvidenceQuality 轻微降低或不降低

---

## 16.2 类型 B｜同构题强方向冲突

例如 D7：

- C20=A：忙也每天维持
- C21=D：本来就不是每天型，一段时间不登很正常

如果两题都属于强答案：

```text
+2 vs -2
```

处理：

1. 标记 `CONTEXT_SENSITIVE`
2. 降低该维 EvidenceQuality
3. 若该维决定 Top 人格，追加一题验证
4. 结果页不要写“你回答矛盾”，而写：

> **你的这一倾向比较看具体情境。**

---

## 16.3 类型 C｜事实型硬矛盾

例如：

```text
G07 = D：基本长期只围绕一款游戏
T22 = B：同时长期维护多款二游
```

这两条不能直接平均。

处理：

1. 暂停依赖该事实的 Hard Gate
2. 触发一条事实澄清题
3. 澄清前：
   - 二游排班师不能确认
   - 版本候鸟也不因这条直接确认
4. 使用澄清结果替代旧事实冲突，旧回答仍保留用于分析题目质量

---

| 领域 | 需要监控的回答 |
|---|---|
| 多游 | G07 vs A10 vs T22 |
| 社区 | G06 vs C22/C23/C24 vs T15/T18/T19 |

> **优先认为 Gate 过粗，而不是优先认为用户乱答。**

# 21. 本轮做出的重要决策

1. **不再使用“24个统一原型中心最近距离”作为最终人格算法。**
2. **人格成立与主人格选择彻底分开。**一个人可确认多个，但只选一个 SSS 主人格。
3. **新增 S17「体验自主度」**，专门防止随心体验派与轻度参与混淆。
4. **新增 F1～F4 派生事实特征**，处理多游并行、跨系统收集、多领域广度与均衡度。
5. **新增 MX 跨领域终局取舍题**，解决重度玩家多个领域全部高的问题。
6. **人格初始确认阈值定为 Fit≥70、独立证据≥3、EvidenceQuality≥60。**这些是工程阈值，不是心理学常模。
7. **标签题用于人格判定时降权到 0.5。**标签可以一题触发，但不让直白自评支配主人格。
8. **Hard Gate 可以淘汰人格候选，但普通单题不能“一票否决”。**
9. **Gate 可以恢复。**后续两条强证据足以重新打开被跳过领域。
10. **矛盾优先解释为情境差异或题目问题，而不是用户不诚实。**
11. **多面体验派明确禁止作为兜底人格。**
12. **后台不限制共鸣人格和标签数量；UI 只限制首屏密度。**
13. **8维光谱继续保留，但必须同时展示证据状态。**
14. **所有人格仍统一 SSS 金色，不做稀有度高低。**

```text
P1_effective >= 1
```

- C01=C/D
- C02=C/D
- C03=C/D

```text
Compat(D1强度侧) < 55
```

则不能仅凭高D5 / 高钻研成为强度经理人。


之一。

# 27. P1.5 题库同步补充

## 27.1 C27｜本命的毕业线

C27 是本命雕刻师的新增条件核心证据：

```text
C27=A → S4+2，强纵向养成直接证据
C27=B → S4+1，纵向养成直接证据
```

仅在本命雕刻师候选成立但 S4 证据不足，或需要和普通本命人格区分时出现。

## 27.2 C28｜无聊但有奖励

C28 是随心体验派的新增通用自主选择证据：

```text
C28=C → S17+1
C28=D → S17+2
```

如果随心体验派 Hard Gate 需要“至少2条主动选择舒服/够用证据”，C28=C/D 可以计为其中1条。

## 27.3 反向题

v0.4题库对以下题做语义反向：

```text
C08 / C11 / C14 / C17 / C19 / C23
```

P0 只读取评分后的 D/S/F/P，不应再依赖这些题的旧字母方向。

## 27.4 A06

A06 只区分：

```text
配队建筑师
vs
高难工程师
```

不再从 D 选项给强度经理人 S3 信号。

## 27.5 题库规模

```text
G 7
M 1
C 28
A 16
T 22
总池 74
```

C27/C28均为条件题，因此普通用户题量不固定增加。


## 27.6 M01 低参与互斥项

P1.5 新增：

```text
H. 没有特别不能缺的，主要看当时兴趣
```

H 与 A～G 互斥。

选择 H 时：

```text
不把任何 M 设为100
所有 M 只按对应 P_effective 计算基础值
```

这主要避免真实低参与/二游观察者候选被迫制造一个虚假的“核心乐趣”。
